## 你需要实测的项目

### 1. 在目标服务器启动和验证 HTTPS

- [ ] 按 [部署说明](数据库与部署.md) 设置服务器域名、数据库密码、管理员初始密码和加密密钥，启动 Compose。
- [ ] 从服务器外打开 HTTPS 地址。确认可以注册新账号，退出后重新登录。确认 `docker compose ps` 中服务正常，浏览器无证书问题。
- [ ] 用管理员和普通用户分别登录。在管理员个人中心可见「全站 AI 设置」；普通用户个人中心只显示账号与个人记录。

### 2. 连接实际 AI 服务

- [ ] 管理员在个人中心输入供应商提供的完整 Chat Completions 地址、模型名和 API 密钥。使用可发送到该供应商的测试素材。
- [ ] 普通账号打开自己的已完成分析，在「片段问答」选一个片段，发送「这段有哪些音符没有识别出指法？」。确认返回真实回答，并能通过片段引用跳回同一视频。
- [ ] 在「片段分析与练习」生成 AI 练习草案，挑一项加入。到「练习计划」修改名称，手动加一条，删除一条并标记另一条为完成。重新登录后检查变化是否保留。
- [ ] 问一个证据不足的问题，例如在纯骨架任务中问具体错音。回答应说明证据不足。检查建议是否可执行，是否把指法候选或未匹配解释成已确认的演奏问题。

### 3. 验收真实演奏分析

- [ ] 至少录一段固定俯拍视频，并同时采集该次演奏的实际 MIDI。建议包含普通音群、和弦、快速换指、黑键、遮挡和左右手交叉。
- [ ] 登录账号 A 上传测试视频。骨架模式检查原片、骨架叠加、声音和下载；指法模式填可见白键音域、四角及偏移。如果画面水平镜像，勾选镜像。用画面中的琴键与 MIDI 音符核对几个触键时刻。
- [ ] 使用带清晰琴声的视频跑一次音频转录。如有相同曲目的参考 MIDI，再跑参考乐谱对照。在原声和乐谱中抽查差异候选，记录转录或对齐产生的误报。
- [ ] 退出后用账号 B 登录，确认历史演奏、问答、练习和曲库都只呈现 B 的数据。再登录 A 检查任务能重新打开。若要测试迁移，按部署说明把已有历史文件显式分配给管理员。

### 4. 计算指法验收指标

选几条指法分析任务，从 `outputs/api` 或服务器媒体卷取出各自的任务目录。以下示例在项目根目录执行，将任务目录替换为实际 ID。

```powershell
python backend/evaluate_fingering.py template --jobs outputs/api/任务ID1 outputs/api/任务ID2 --labels data/annotations/fingering_labels.csv
python backend/evaluate_fingering.py evaluate --jobs outputs/api/任务ID1 outputs/api/任务ID2 --labels data/annotations/fingering_labels.csv --output outputs/reports/fingering_metrics.json
```

两条命令之间填写 CSV。只查看原始演奏，避免预先查看系统候选。手别填 `left`、`right` 或 `unknown`。能确认时将指号填 `1` 到 `5`，从拇指到小指。`scenario` 可填 `slow`、`chord`、`occlusion`、`black_key` 等场景。尚未检查的行保留空白。

生成报告后记录有手部检出的音符比例、候选覆盖率、拒识比例、左右手和指法准确率。先审查样本数量、标签和各场景结果，再确定验收阈值。能力评分需另有稳定量表与人工对照，当前页面提供片段统计和练习建议。
